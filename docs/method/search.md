# Search and the pool

Part of the method (`docs/methodology.md` is the index). Measured results and trials: `docs/method/history.md`.

## 5. Search

Sentences are where we search, paragraphs where we work: a sentence states one thing, so an asset or a measure is found in a sentence, and the paragraph around it is what a model or a person reads to decide.

**Search units (`src/wbg_portfolio/units.py`).** Every sentence of the narrative and annex paragraphs; each footnote, whole (footnotes are mostly references, which a sentence splitter would cut into nonsense); and each table row whose cells read as prose (`units.prose_row`: at least 15 words, a verb, numbers under a fifth of the tokens; rows in grievance-redress sections are not taken). A prose row of 60 words or fewer is one unit with its caption and column names; a longer one is cut at each cell boundary and each bullet inside a cell, then into sentences (`units._row_sentences`), each read with the table's caption in front. Each unit carries its paragraph, document, the project of the document part it sits in, block, section, component and sub-component number in its own document's numbering, and `component_key`, that component's `name_key`, which finds the same component in another document when a restructuring renumbered it.

**What is not searched** (`units.left_out`; nothing is deleted, but these are not embedded or searched): a *reference*, a footnote that only cites a source or titles a table or figure (under four words; under twelve words with no verb; or under 40 words with a year or a link and a source); a *fragment*, a sentence of under four words or a title of ten words or fewer nearly all capitalised; an *indicator*, a prose table row in a results-framework, indicator or monitoring section (`units.RESULTS_SECTION`), a target rather than a commitment. A unit that says "will" or "shall" is always searched, and so is a list item with a lead-in. A unit whose embedded text, lead-in included, is word for word that of an earlier unit (in document and unit order) is a *copy* (`copy_of`): additional financing and restructuring papers repeat their appraisal document. A copy is searched once, through the first unit, whose `copies` column lists the others.

**List items carry their lead-in.** A list item ("(b) towers;") is embedded with the sentence that introduces its list ("Sub-component 1.1 will finance:") in front. An item is a sentence on any line after the paragraph's first (section 2.2), or one opening with an enumerator (`sentences.ITEM_MARKER`); the lead-in is the last sentence before it that is not an item. A list that starts its own paragraph has none. The unit stays the item: its id, offsets and hash are its own; the cache is keyed on the text embedded.

**Embedding (`src/wbg_portfolio/embed.py`, the `embed` stage).** Each distinct unit text, lead-in in front, is embedded once by a pinned model (`openai/text-embedding-3-large`, 3,072 dimensions, through OpenRouter with the provider pinned and fallbacks refused) and cached under the SHA-256 of the text, so a re-run, an interrupted run or a larger cohort pays only for text not seen before. `--embed-context section` puts the section title and component heading in front as well; the index records the hash of the text embedded, so a changed design is a new index. A vector is stored only if it has the right length and a norm near 1. Before embedding, each unit's text is cut from the cleaned file by its offsets and checked against the checksum recorded at cleaning. Output: `data/embeddings/sentence_emb.npy` (one row per unit) and `sentence_index.csv`, with a manifest of the model served, tokens and spend. The key: `$WBG_OPENROUTER_KEY`, else `.secrets/wbg-openrouter-key` in the main checkout, mode 0600 (`api.key`); a key file readable by anyone else is refused, and a key is never an argument.

**Label sets** (`src/wbg_portfolio/labels.py`). `inputs/taxonomy/` holds the pipeline's own set, the assets, changed rarely and deliberately; `analysis/labels/` holds analysis sets, the measures and anything being tried, added and revised freely (`analysis/README.md`). `<set>.csv` has one row per label (an id, a name, a definition, whether it is active), `<set>_queries.csv` any number of search phrases per label, `<set>_patterns.csv` optional word patterns, `<set>_types.csv` the approved types. The grade scale is shared (`analysis/labels/scale.csv`); a `<set>_scale.csv` beside a set overrides it. Each label is searched with its definition ("name: definition") and with each of its phrases, since a phrase ranks what a broad definition does not. Every command takes a set by name, whichever folder holds it; the same name in both is refused.

**Scoring (`src/wbg_portfolio/search.py`, the `search` stage).** Every query text is embedded and cached like any text, and every unit is scored against every query by cosine. All scores are kept (`scores.npy`, units by queries, with `queries.csv` naming each column); nothing is cut off. A run is written to `data/search/<set>-<version>/`, where the version is a SHA-256 over the query texts, the model and the sentence index: a revised phrase gives a new version that embeds only what changed, and an unchanged set is not scored again. `search.hits()` and `search.paragraph_rollup()` filter a version (minimum cosine, minimum percentile within a query, best N, labels, projects, kinds) for analysis; no filter is the default.

## 5a. The pool, without a reader

A measure's pool is built inside the funnel (section 5g) from two routes that read no text with a model: the units a measure's word patterns match (lead-in included) and every unit whose best cosine over the measure's phrases reaches the gate (the fitted gate, else `measure.gate_cosine`). Each score row carries its route (pattern, embedding, both, feedback or stored), round, rank and cosine, columns to filter on and never a cut.
