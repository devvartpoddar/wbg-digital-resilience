# Packages to assets and to commitments

Part of the method (`docs/methodology.md` is the index). Measured results and trials: `docs/method/history.md`.

## 5e. Packages to assets and to commitments (`./wbg_portfolio run --only link`)

The plan's component column joins a package to the appraisal document only where the plan printed one and the parser matched it, and a package description does not sit near the committed sentences by cosine. So a package is linked to a commitment in two ways, each a stored answer, and every link says which it is (`commitment_package_links.strength`).

**Package to asset** (`checks.package_assets`, `second.package_asset_second`). Every package description in scope (placeholders left out) is embedded once and ranked against the asset phrases; its best `link.asset_top` assets go to the decision model, one graded question each: "How far is the procurement package in the 'package' field for {asset}?", the asset's definition and the shared rule, on the taxonomy scale with "package" for "sentence" (score P(2)+P(3)), with the package text and its plan component as the state. A package has an asset (`package_assets.has_asset`) when its score (through the package-asset layer once fitted) reaches `link.asset_yes`, or from `link.asset_band_low` up to it when the chat model's second look says yes (kind `package_asset_second`: yes or no on the package description, category, component and the asset's definition; its wording is unchanged). A missing or unreadable second look is never a yes (`decide.package_asset_sets`). Most of a plan (works, vehicles, audits) has none.

**Package asset type** (`second.package_asset_subtype`). Every package x asset that counts is asked the sentences' type question with the package as subject ("Which type of {asset} is the procurement package in the 'package' field about?", the types by name and unspecified), by the chat model. Kind `package_asset_subtype`; published as `package_assets.subtype_id`. The evaluation sampler reads it under the same names.

**The links** (`decide.link_strength_rows`, read at publish). A committed, digital sentence and a package of the same project are linked:

- **`strong`**: the package, asked on its own, is about the sentence's measure (kind `package_measure`, `checks.package_measure`): does the measure apply to the procurement package, that is, is what the package procures the measure, named or clearly implied in the package's own description (`questions.package_measure_question`). It is asked of every package in scope that is not a placeholder, with or without an asset (so a cybersecurity service with no asset can be strongly linked), but only about its `link.package_measure_top` (3) likeliest measures: those of the measures its project has a kept sentence for whose phrases and definition its description is closest to by cosine (the same embedding the package-to-asset gate uses), plus every pair the store already answers (nothing paid for is dropped). It is strong at P(yes) of `link.strong_yes` or more. Every kept sentence of that measure in the project is then linked to the package; a strong link does not need the package to have an asset.
- **`asset`**: they share a top-level asset (connectivity, hosting, platforms, monitoring and control). No model is asked at this step: it is read from the sentence's asset (first pass or second look, at the levels `dashboard.commitment_link_levels` counts) and the package's. It says only that both concern the same kind of asset, not that the package delivers the commitment. Label it "same asset".

A pair that is both is one row, `strong`, with its `shared_asset_ids` filled. The links are the models' reading, not a person's; documented is not done.

**Levels (2026-11-21).** Each link also has a level (`level`, `level_rank` 1 to 5), from most to least telling. The levels add no link and remove none; they only order the same links, and the views and the reader list links in that order.

| Level | Means | What it can be trusted to mean |
|---|---|---|
| 1 `strong` | the package, read alone, names or clearly implies the measure | in a reading of 40 such links (2026-11-21, read by an agent, not graded by people), 34 were plainly the thing the measure needs; it says the package serves the measure in that project, not that it delivers that particular sentence, and not that it is signed or built (a third of linked packages are cancelled) |
| 2 `type_and_component` | the sentence and the package have the same asset type (ignoring unspecified) and the same top-level component | the same kind of thing in the same part of the project; still not a claim that the package delivers the commitment |
| 3 `type` | the same asset type, components different or unknown | the same kind of thing somewhere in the project |
| 4 `component` | the same asset (any type) and the same top-level component | in a reading of 45 same-asset links in the same component (the same reading), 5 were the thing, 31 the same asset but a different thing, 9 unrelated; the same component halves the unrelated share (about 20 against 60 per cent) but did not measurably raise the right share |
| 5 `asset` | the same top-level asset only | in readings of same-asset links, about 10 to 20 per cent were the thing; read it as "same kind of asset", never as a procurement for the commitment |

The parts are published: `same_type`, `component_relation` (`same`, `different`, or `unknown` when either side has no component; components are compared at the top level, `2.1` and `Component 2` read as 2, letters kept, and only "same" when both are known and equal), `sentence_component`, `package_component`. Two flags on the link's package help a reader set links aside: `package_cancelled` (its plan status is Canceled or Terminated: `decide.CANCELLED`, the same list as the Cancelled package status) and `package_generic` (its description is about running the project: project management, audit, vehicles, office furniture, workshops, per diem, accounting, salaries; a whole-word pattern in `decide.GENERIC`, with no bare "communication", so "Unified Communication Tools" is not generic, and an audit of security or of a system is not generic). Both are flags to filter on, never cuts. The component signal is weak: on the 2026-11-21 data a component was missing on one side of 43 per cent of links, packages have no sub-component in 99 per cent of cases, and in the largest projects most links fall in one or two components.

**Output.** `wbg.scores` kinds `package_asset`, `package_asset_second`, `package_asset_subtype`, `package_measure`; at publish `wbg.package_assets` (`has_asset`, `subtype_id`) and `wbg.commitment_package_links` (`project_id`, `label_set`, `unit_id`, `package_id`, `strength`, `shared_asset_ids`, `strong_p`, `package_category`, `level`, `level_rank`, `same_type`, `component_relation`, `sentence_component`, `package_component`, `package_cancelled`, `package_generic`), read through `package_assets_in_context`, `commitment_package_links_in_context` and `packages_with_commitments`.

**What the app reads.** `commitment_package_status` (read by `app.packages` and `app.coming_up`) has one row per commitment and linked package, fed from `commitment_package_links` through the commitment's sentences: a strong link and a same-asset link are both links. It carries `strength` (`strong` when any of its links is strong, else `asset`), `level` and `level_rank` (the best level among the commitment's sentences' links), the package's two flags, and `link_probability`, the strongest strong-link probability (`strong_p`), which is null when every link is by shared asset. The same holds for `probability` and `link_posterior_probability` in `commitment_packages_in_context` (the same rows as `commitment_package_links_in_context`, under the name earlier readers use) and `best_commitment_probability` in `packages_with_commitments`. `dashboard_settings.package_link_min_probability` is `link.strong_yes`. A commitment with only a same-asset link now has a linked package, so the share of linked commitments is higher than when only the old question linked them; read a same-asset link as the weaker of the two.

**Checking.** The draw takes package assets by band of their probability; `./wbg_portfolio check fill` stores them (kind `package_asset`), and the evaluation reports precision and recall among the pairs asked. The strong link and the same-asset link have no graded sample yet.
