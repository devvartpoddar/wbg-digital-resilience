# Packages to assets and to commitments

Part of the method (`docs/methodology.md` is the index). Measured results and trials: `docs/method/history.md`.

## 5e. Packages to assets and to commitments (`./wbg_portfolio run --only link`)

The plan's component column joins a package to the appraisal document only where the plan printed one and the parser matched it, and a package description does not sit near the committed sentences by cosine. So a package is linked to a commitment in two ways, each a stored answer, and every link says which it is (`commitment_package_links.strength`).

**Package to asset** (`checks.package_assets`, `second.package_asset_second`). Every package description in scope (placeholders left out) is embedded once and ranked against the asset phrases; its best `link.asset_top` assets go to the decision model, one fit question each: does the package buy, build, install, connect, operate or design the asset, with the package text and its plan component as the state. A package has an asset when its P(yes) (through the package-asset layer once fitted) reaches `link.asset_yes`, or from `link.asset_band_low` up to it when the chat model's second look says yes (kind `package_asset_second`: yes or no on the package description, category, component and the asset's definition). A missing or unreadable second look is never a yes (`decide.package_asset_sets`). Most of a plan (works, vehicles, audits) has none.

**The links** (`decide.link_strength_rows`, read at publish). A committed, digital sentence and a package of the same project are linked:

- **`strong`**: the package, asked on its own, is about the sentence's measure (kind `package_measure`, `checks.package_measure`): does the measure apply to the procurement package, that is, is what the package procures the measure, named or clearly implied in the package's own description (`questions.package_measure_question`). It is asked for each package that has an asset, against each measure its project has at least one committed, digital sentence for, and is strong at P(yes) of `link.strong_yes` or more. Every committed, digital sentence of that measure in the project is then linked to the package.
- **`asset`**: they share a top-level asset (connectivity, hosting, platforms, monitoring and control). No model is asked at this step: it is read from the sentence's asset (first pass or second look, at the levels `dashboard.commitment_link_levels` counts) and the package's. It says only that both concern the same kind of asset, not that the package delivers the commitment. Label it "same asset".

A pair that is both is one row, `strong`, with its `shared_asset_ids` filled. The links are the models' reading, not a person's; documented is not done.

**Output.** `wbg.scores` kinds `package_asset`, `package_asset_second`, `package_measure`; at publish `wbg.package_assets` and `wbg.commitment_package_links` (`project_id`, `label_set`, `unit_id`, `package_id`, `strength`, `shared_asset_ids`, `strong_p`, `package_category`), read through `package_assets_in_context`, `commitment_package_links_in_context` and `packages_with_commitments`.

**What the app reads.** `commitment_package_status` (read by `app.packages` and `app.coming_up`) has one row per commitment and linked package, fed from `commitment_package_links` through the commitment's sentences: a strong link and a same-asset link are both links. It carries `strength` (`strong` when any of its links is strong, else `asset`) and `link_probability`, the strongest strong-link probability (`strong_p`), which is null when every link is by shared asset. The same holds for `probability` and `link_posterior_probability` in `commitment_packages_in_context` (the same rows as `commitment_package_links_in_context`, under the name earlier readers use) and `best_commitment_probability` in `packages_with_commitments`. `dashboard_settings.package_link_min_probability` is `link.strong_yes`. A commitment with only a same-asset link now has a linked package, so the share of linked commitments is higher than when only the old question linked them; read a same-asset link as the weaker of the two.

**Checking.** The draw takes package assets by band of their probability; `./wbg_portfolio check fill` stores them (kind `package_asset`), and the evaluation reports precision and recall among the pairs asked. The strong link and the same-asset link have no graded sample yet.
