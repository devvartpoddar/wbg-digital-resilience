# Packages to assets and commitments

Part of the method (`docs/methodology.md` is the index). Measured results and trials: `docs/method/history.md`.

## 5e. Packages to assets and to commitments (`src/link_packages.py`, `./wbg link`)

The procurement plan's component column links a package to the appraisal document only where the plan printed one and the parser matched it: on the 2026-10-20 run that reached about a fifth of the paragraphs the model had read, and only 199 of 803 committed sentences could be put next to a package that way. The connection an advisor needs is one of meaning: the commitment says "resilience measures for the government network", the package says "GovNet phase 2: supply and installation of core equipment", and no number joins them. A first probe (cosine between a package description and the committed sentences of its project) showed the two kinds of text do not sit near each other (0.2 to 0.45, with no gap between a right pair and a wrong one), so the link is made in two steps through what they share, the asset, and each step is a decision-model answer, stored and scored like the rest:

1. **Package to asset.** Every package description in scope (placeholders left out) is embedded once with the sentence model and cached under its text's SHA-256 (the same cache as the sentences), and ranked against the asset taxonomy's phrases and definitions (`inputs/taxonomy/assets_queries.csv`). Its best `ASSET_TOP` assets by cosine (4) go to the decision model, one yes/no each, with the package text and its plan component as the state: "does the procurement package buy, build, install, connect, operate or design fiber networks? Fiber networks means: ...". Every answer is kept with its cosine rank, and the report counts the yes answers at the last rank: if there are many there, the depth is too small and the next run says so before a threshold does. A package may buy several assets; none at 0.5 means the package is not digital, which is most of a plan (works, vehicles, audits).
2. **Commitment to package, many to many.** For every measure with a current run, each committed unit (the top grade) is paired with the packages of its project that share an asset, or an asset in the same reading group (`inputs/taxonomy/assets_groups.csv`), with the assets the unit's own second-pass answers named (`assets_yes`, else its linked asset). Each pair goes to the decision model once, with the commitment sentence, the package description and both components as the state, and one yes/no: would carrying out this package be where the commitment is delivered or applied? One commitment can link to four packages and one package to several commitments; the yes probability is stored on every pair, and nothing is cut in the files.
3. **Commitment to package by the measure (route `measure`).** A package that buys no digital asset (a climate risk assessment consultancy, works to raise tower sites) never meets a commitment by asset. So each committed unit is also paired with its project's `MEASURE_TOP` (3) packages nearest the measure itself, by the best cosine of the package description's stored embedding to the measure's phrases and definition, leaving out packages already paired by asset; the same yes/no question is asked. `route`, `measure_rank` and `measure_cosine` are kept on each pair, and the report counts the yes answers by rank (yes answers at the last rank mean a deeper search would find more). Dev's decision, 2026-10-20.

4. **How many packages a commitment keeps: by its scope.** The link stage pairs widely; the views decide how many links a sentence keeps (`commitment_package_status`, 2026-10-21). A sentence that is one specific investment (`wbg.unit_scope`, section 5c) keeps its `dashboard_settings.investment_package_top` (3) most likely packages at the threshold; a rule on everything of a kind the project buys keeps every one. Neither a cap nor a cut-off alone fits both: "All IT equipment procured … will be … Energy Star" rightly links to 95 packages, while "a secure data center and backup center" linked to 38; and 151 committed sentences had more than 20 links each. Capping every sentence at 3 would have cut the 9,843 links to 3,032; the cap applies to investments only.

Why the asset is the bridge and not a cosine or a component: the asset is what both texts name (a climate-annex sentence about "the sites" was already read with its paragraph to answer which asset, in section 5c), the reading group absorbs the taxonomy's finer splits (a commitment on "the national network" and a package for "metropolitan fibre rings" both sit in networks and connectivity), and the pair question is then asked only of pairs that could be right: on the 2026-10-20 runs the 699 sentence-linked commitments and 7,846 packages of their projects make 54,000 pairs in all, and the asset gate was meant to keep the question to a few thousand; pairing on a shared reading group as well made it 98,539 on the first full run (`history.md`), so narrowing the pairing is the lever if the link is run again at scale. Both questions are stored per model, state and question (`src/answers.py`), so a deeper `ASSET_TOP` asks only the added rank and a new measure asks only its own pairs. The link is unmeasured until a sheet is graded. `./wbg check all` draws 70 commitment and package pairs from the current link run into the workbook's `package links` tab, by band of the link probability (10 below 0.3, 15 each from 0.3 to 0.5, 0.5 to 0.7, 0.7 to 0.9 and above), for a person to answer yes, no or unsure; `--evaluate` stores the answers in `data/labels/package_links.csv`, keyed by both texts' SHA-256 and the question's, and reports precision and recall at each threshold from 0.3 to 0.9, weighted back to the bands, in `data/reports/evaluate_links.md`. Recall there is among the pairs the link asked, not every package.

Output: `data/links/packages-<version>/package_assets.csv` (package, asset, cosine, cosine rank, probability) and `commitment_packages.csv` (measure set, run, unit, package, project, the shared assets and groups, probability), a manifest with the questions, the measure runs linked, the models served, calls and cost, and `data/reports/link_packages.txt`. The version is a SHA-256 over the stage's version, the packages table, the asset phrases and definitions, the questions, the model, the depth and the measure runs; a new measure run is therefore a new link run, which reads the store for every pair it has seen. Loaded as `wbg.package_assets` and `wbg.commitment_packages`, read through `wbg.package_assets_in_context`, `wbg.commitment_packages_in_context` and `wbg.packages_with_commitments` (one row per package with the assets it buys, the measures linked to it and how many commitments, at the 0.5 reading threshold).
