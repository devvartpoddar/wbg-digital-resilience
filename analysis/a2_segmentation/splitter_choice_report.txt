A2b - splitter variant choice
==============================================================================

ASSUMPTIONS
------------------------------------------------------------------------------
1. A token here is a whitespace-delimited token of the clause as it
   resolves from data/clean/. clauses.csv carries offsets, not text, and
   no token count. Both variants are counted the same way, so the
   comparison holds even if the absolute share differs from the probe's
   by a few points. If the parser's token count was meant instead, the
   <=4 column moves and the ranking does not.

2. The acceptance half of the criterion is check_segmentation.py's, run
   as a subprocess once per variant against that variant's own table.
   Its report lands beside that table under data/scratch/, not in the
   repository; the variant that is kept is re-scored into
   analysis/a2_segmentation/report.txt so the committed report describes
   the splitter that is actually in the tree.

3. The four-token cut is the probe's, not a threshold anyone tuned.
